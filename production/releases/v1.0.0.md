# Flop Hoops 1.0.0: release candidate

A retro, physics-based, two-ballers-a-side basketball game. One jump key and one bounce key per team, two players on one
keyboard or one against the computer. Plays offline in the browser. Keyboard required (the title says so on touch-only devices).

## What ships
- The game folder `prototypes/flop-hoops/` as a web build: `dist/` and `flop-hoops-1.0.0-web.zip` (index.html at the top of the zip,
  14 files, about 592 KB, 197 KB zipped), made by `bash prototypes/flop-hoops/tools/release.sh`. Build output is not committed.
- `LICENSES.txt` in the build: Matter.js 0.19.0 (MIT) and Departure Mono 1.500 (SIL OFL 1.1), the only third-party files.
- Everything else is original code; all art is drawn in code and all sound is synthesised at run time.

## Bugs fixed for this release
1. `rock_angle` at its minimum (0, reachable in ADVANCED settings) made every player's position NaN and broke the match. Its minimum
   is now 0.1 and the code divides by at least 0.05.
2. A corrupt or hand-edited saved setting (for example `ai_style: 7.6`) was loaded without being snapped to its step and crashed the
   title screen. Saved values are now clamped and snapped like ones set in the menu; non-numbers, non-objects and arrays are ignored.
3. In a browser with no Web Audio (or one that refuses it), starting the sound threw inside the key handler before the key registered,
   so the game could not be started. Sound now fails quietly: the game plays silent.
4. The scoreboard said "LEVEL" when the score was tied, which reads like the CPU level. It says "TIED".
5. Also from the earlier iterations: the two-point line's aim help no longer applies near the other team's line.

## Checks run (headless Chromium)
- Fuzz: 18 matches (VS CPU, 2 players, CPU vs CPU; levels 1 and 6; 3 seeds), 9000 steps each, random keys and pauses: no page errors,
  no NaN, ball and players always on the court, every match reached play.
- Every one of the 220 settings at its minimum and at its maximum, 500 steps each: no errors after fix 1 (the only failure found).
- 2,500 random clicks, moves, wheel turns and keys across the title, settings, pause and watch screens: no errors, no soft-lock.
- Saved settings: garbage JSON, out-of-range and non-numeric values, `null`, `[]`, and storage blocked outright: the game starts and plays.
- Window sizes 320x240 to 1920x1080: the canvas scales to fit with no overflow.
- Cost per step about 0.5 ms, about 6 ms with drawing (7.6 ms at maximum particles): well inside 16 ms.
- The zip, unpacked on its own with the network blocked and the real game loop running: loads, title, VS CPU, play; the only requests are
  the build's own files; no errors.

## Known limits
- Keyboard only: no touch or gamepad controls. Online play is not built (out of scope in the brief).
- Not play-tested by a person across a whole session; feel (the CPU's styles, the line's help, the sounds) is untested by hand.
- Target platform not chosen (`platform.cert_tier` is unset): the build is a plain web build that suits itch.io or any static host.
  Page copy, screenshots and age tags for a store page are not written.
- No tag or GitHub release has been made; creating one is the next step once this is approved.
